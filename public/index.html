Core Security Features

Comprehensive evidence protection, verification, and auditability

⬆️

Upload & SHA-256 Hashing

Streams uploaded files through cryptographic SHA-256 engines to calculate deterministic 64-character lowercase hex hashes server-side.

🛑

Duplicate Detection

Pre-upload hash indexing detects duplicate evidence submissions instantly, enforcing integrity and logging duplicate collision attempts.

✅

Cryptographic Verification

Compare suspect or presented files against registered evidence records to mathematically verify identical content or highlight altered bytes.

⛓️

Hash-Chain Ledger

Every evidence record is sealed into an immutable block linking to its predecessor's cryptographic hash, preventing backdated record alterations.

📋

Append-Only Audit Trail

How It Works

Step-by-step custody maintenance from acquisition to court presentation

1

Authenticate

Investigators sign in with JWT authentication and bcrypt password verification, scoping capabilities to their assigned operational role.

2

Acquire & Stream

The forensic file is uploaded alongside descriptive metadata. The server streams the payload through SHA-256 hashing to generate a unique digital fingerprint.

3

Seal into Block

The evidence hash is bundled into a sequential block that references the previous block's hash, forming an unbroken, tamper-evident cryptographic chain.

4

Log Audit Event

An append-only audit entry logs the operator, timestamp, action, and resulting block number into the hashed audit trail.

5

Verify at Court

Any party can upload a copy of the digital artifact. EvidenceGuard compares the file's current hash against the immutable ledger hash.

6

Immediate Verdict

If a single bit was modified, the system outputs a TAMPERED verdict, pinpoints character differences, and records a security incident.

Security Architecture

What is protected and how EvidenceGuard guarantees chain-of-custody defense

🔐 bcrypt Password Hashing

User passwords are salted and hashed using bcrypt with an adaptive cost factor of 10. Passwords never reside in plaintext in database storage or logs.

🍪 Secure JWT Cookies

Session authentication tokens are stored in HTTP-only, SameSite cookies with strict expiration and no exposure to client JavaScript.

🛡️ Role-Based Access (RBAC)

Enforces server-side authorization middleware checking roles across every API endpoint. Viewers cannot upload; non-admins cannot delete or manage users.

⚡ Server-Side SHA-256 Hashing

Hashes are calculated server-side from binary file streams. Even if client-side validation is bypassed, the server enforces independent verification.

📋 Append-Only Audit Trail

Every audit log entry contains a deterministic hash linking to the previous entry's hash. Updates and deletions are blocked at the Mongoose middleware level.

⛓️ Hash-Linked Block Ledger

Blocks are indexed and linked sequentially. Any attempt to modify a historical record breaks all downstream hashes, detected in sub-second verification runs.
